这是一个可复用的静态文档站模板。它适合产品手册、SDK 文档、团队规范等以内容为
主的站点。复制仓库后，主要通过修改 JSON 配置和 MDX 文档，就能建立自己的文档站，
不需要先理解全部 Next.js 代码。每种语言的正文放在 `docs/<语言>/`，公开地址带同样
的前缀。语言写在 `website/meta/site.json` 的 `locales` 里，没有单独的默认语言。

## 模板能力 {id="features"}

模板已经内置这些能力：

- **静态导出**：`npm run build` 生成可部署到任意静态托管的 `out/` 目录。
- **MDX 文档**：在 `docs/<语言>/` 中用 Markdown 编写内容，并嵌入现成组件。
- **多语言**：页头可以切换语言。搜索只返回当前语言的页面。
- **响应式导航**：顶部导航、左侧边栏和页脚都由配置驱动。
- **本地搜索**：生产构建会生成 Pagefind 索引，支持离线检索。
- **项目路径部署**：内置 GitHub Actions，普通仓库可直接发布到
  `https://<用户名>.github.io/<仓库名>/`。
- **Example 侧栏**：在宽屏中把简短、可执行的例子放在正文右侧，移动端自动回到正文
  流。

## 目录结构 {id="structure"}

日常使用时，优先关注这些目录。文档在仓库根目录，站点代码在 `website/`：

```text
.
├── docs/                         # 按语言分目录的 MDX
│   ├── zh-CN/                    # 中文手册
│   │   ├── getting-started/
│   │   ├── writing/
│   │   └── publishing/
│   └── en/                       # 英文手册
│       ├── getting-started/
│       ├── writing/
│       └── publishing/
└── website/
    ├── meta/
    │   ├── site.json             # locales：每种语言的名称、导航和页脚
    │   ├── sidebars.json         # 所有语言共用的页面顺序，url 不带语言
    │   └── type-annotations.json
    ├── pages/
    │   └── index.tsx             # 语言列表
    ├── public/                   # 静态资源
    └── src/                      # 站点组件、样式与模板逻辑
```

通常不需要改动 `src/`。只有在扩展组件或调整样式时才需要进入这里。

## 配置关系 {id="configuration"}

三个位置共同决定一篇文档如何出现：

| 位置                          | 决定什么                               |
| ----------------------------- | -------------------------------------- |
| `docs/<语言>/<section>/*.mdx` | 该语言的页面内容、标题、摘要和右侧目录 |
| `website/meta/site.json`      | 每种语言的标题、顶部导航和页脚         |
| `website/meta/sidebars.json`  | 所有语言共用的左侧顺序，`url` 不带语言 |

`section` 是它们之间的连接键。例如 `docs/zh-CN/writing/assets.mdx` 的 frontmatter 使用
`section: writing`。`locales.zh-CN.sections` 和 `sidebars.json` 里也都要有
`writing`。公开地址是 `/zh-CN/writing/assets`。

编写章先讲怎么写页面。后半用一个虚构产品来演示整站配置，名字叫 Acme SDK，用来代
表你自己的产品文档。你会为它增加 `/zh-CN/guide` 大章节，并修改语言列表页的品牌信息。
发布章再验证搜索并部署。走完后，把名称和正文换成自己的产品。

## 推荐使用流程 {id="workflow"}

第一次使用模板时，建议按下面的顺序完成：

1. 从 GitHub 模板创建自己的仓库并在本地启动站点。
2. 按快速开始写第一篇 MDX。
3. 在编写章学习页面、组件和图片，再改站点名称、大章节和首页。
4. 用 `npm run preview:search` 验证搜索和静态导出效果。
5. 推送到 `main`，由内置工作流部署 GitHub Pages。

每次增删页面后都运行测试和生产构建。测试会检查配置、路由、frontmatter、侧边栏和
右侧目录是否彼此一致。
