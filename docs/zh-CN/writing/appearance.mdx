上一页定好了大章节。这一页改首页、颜色和图标。这些信息都在配置和首页里，通常不
需要修改组件逻辑。先换文字和颜色，再决定要不要调整布局。

## 站点身份 {id="identity"}

| 位置                          | 需要替换的内容                                     |
| ----------------------------- | -------------------------------------------------- |
| `meta/site.json`              | 组织、仓库、主题色，以及每种语言的标题、导航和页脚 |
| `public/manifest.webmanifest` | `name`、`short_name`、`theme_color`                |
| `pages/index.tsx`             | 根路径只列出语言，通常不用改成某一种语言的落地页   |
| `README.md`                   | 仓库对外介绍和示例地址                             |

<Infobox title="先搜索占位符">

运行下面的命令可以一次找出常见占位符：

```bash
rg 'Documentation Template|Docs Template|Your Organization|your-org|example\.com'
```

修改完成后再次运行；没有输出，表示这些占位符已经清理完毕。

</Infobox>

以 Acme SDK 为例，`meta/site.json` 中的站点身份可以改成：

```json
{
  "company": "Acme",
  "companyUrl": "https://acme.example",
  "repo": "acme/sdk-docs",
  "theme": "#0a8f6a",
  "locales": {
    "zh-CN": {
      "label": "中文",
      "lang": "zh-CN",
      "title": "Acme SDK",
      "description": "Acme SDK 文档",
      "slogan": "用 Acme 构建"
    }
  }
}
```

这里只展示需要替换的字段。不要删除该语言里的 `sections`、`navigation`、`footer`
和 `ui`。预期浏览器标题、左上角名称、源码链接和页脚组织信息一起更新。

再把 `public/manifest.webmanifest` 完整替换为：

```json
{
  "theme_color": "#0a8f6a",
  "background_color": "#ffffff",
  "display": "minimal-ui",
  "scope": ".",
  "start_url": ".",
  "name": "Acme SDK Docs",
  "short_name": "Acme SDK"
}
```

`scope` 和 `start_url` 保持相对路径，部署到 GitHub Pages 子路径时才能由浏览器正
确解析。刷新页面后，在开发者工具的 Application → Manifest 中应看到新名称和主题色
。

## 首页内容 {id="homepage"}

`pages/index.tsx` 是根路径 `/`。它列出 `locales` 里的语言，每张卡片进入该语言的
第一章。这里不是中文文档的首页，也不要改成只服务一种语言的落地页。

每种语言的标题和说明写在 `locales.<语言>.title` 与 `description`。读者进入
`/zh-CN/getting-started` 之后，右上角才是这一语言的章节导航。

`LandingCard` 是首页组件，不能直接写在 MDX 文档中。文档作者可用的组件及实时效果
集中在 [MDX 组件](/zh-CN/writing/mdx-components)。

## 章节主题 {id="themes"}

在该语言的 `locales.<语言>.sections[].theme` 中选择页面主题：

| 名称      | 适合用途             |
| --------- | -------------------- |
| `blue`    | 通用、技术与默认章节 |
| `green`   | 快速开始、成功路径   |
| `purple`  | API、进阶功能        |
| `nightly` | 实验性或预览功能     |
| `legacy`  | 旧版本或归档内容     |

颜色变量和 `.theme-*` 类定义在 `src/styles/layout.sass`。如果新增主题名，要同时
增加对应类和四个颜色变量：主色、深色、浅色背景和半透明背景。

根级 `site.json.theme` 是浏览器 UI 颜色；manifest 的 `theme_color` 是安装后应用
的主题色。它们不会改变章节颜色。

例如，把 Acme 指南的配置设为：

```json
{ "id": "guide", "title": "产品指南", "theme": "green" }
```

保存后进入 `/zh-CN/guide`，章节强调色应变为绿色；其他章节仍使用各自的 theme。

## 字体与图标 {id="assets"}

- 字体文件位于 `src/fonts/`，字体族和字重在 `src/styles/layout.sass` 定义。
- 站点静态图片放入 `public/`，例如 `public/images/logo.svg`。
- manifest 图标需要在 `public/manifest.webmanifest` 的 `icons` 数组中声明；模板
  默认只提供基础 manifest，没有预置应用图标。
- 图片引用规则和 GitHub Pages 子路径处理见 [图片与链接](/zh-CN/writing/assets)。

新增应用图标时，可将 `public/icons/icon-192.png` 放入仓库，再在 manifest 中增加
：

```json
"icons": [
  {
    "src": "icons/icon-192.png",
    "sizes": "192x192",
    "type": "image/png"
  }
]
```

图标 `src` 使用相对路径，不要写仓库名。重新构建后，在 Application → Manifest 中
应能预览该图标。

## 定制边界 {id="boundary"}

只替换内容和品牌时，优先停留在仓库根目录的 `docs/`，以及 `website/` 中的
`meta/`、`public/` 和 `pages/index.tsx`。需要改变导航结构、Example 位置或组件视觉时，再修改
`src/components/` 和 `src/styles/`，并补充对应测试。

每次修改样式后，至少在桌面和窄屏各检查一次首页、普通文档页、长代码块和 Example
侧栏。最后运行 `npm test -- --runInBand` 和 `npm run build`；二者都成功才说明品
牌配置没有破坏导航或静态导出。

外观改完后，继续 [本地搜索](/zh-CN/publishing)，确认读者能找到这些页面。
