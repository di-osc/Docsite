## 路由规则 {id="routes"}

文件放在哪个目录、叫什么名字，决定它的地址：

| 文件                               | 路由                       |
| ---------------------------------- | -------------------------- |
| `docs/<语言>/<section>/index.mdx`  | `/<语言>/<section>`        |
| `docs/<语言>/<section>/<page>.mdx` | `/<语言>/<section>/<page>` |

你刚创建的文件就是这条规则：

- `docs/zh-CN/getting-started/hello.mdx` → `/zh-CN/getting-started/hello`

本手册自己的页面也一样：

- `docs/zh-CN/writing/index.mdx` → `/zh-CN/writing`
- `docs/zh-CN/writing/mdx-components.mdx` → `/zh-CN/writing/mdx-components`

地址始终带着语言目录。文件系统顺序不会影响导航。`index.mdx` 是大章节入口，其余
文件名会直接成为 URL 的一部分，建议使用小写英文和连字符。

## 加入侧边栏 {id="sidebars"}

`website/meta/sidebars.json` 同时控制：

- 左侧导航的分组与页面顺序
- 文档页底部的“下一篇”顺序

打开这个文件，找到 `"section": "getting-started"`。在“快速开始”后面加上“你好”。
只改这一组的 `items`，不要替换整个文件，否则“编写”“发布”会从左侧导航消失：

```json
{
  "label": { "zh-CN": "入门", "en": "Getting started" },
  "items": [
    { "text": "模板概览", "url": "/getting-started" },
    { "text": "快速开始", "url": "/getting-started/quickstart" },
    { "text": "你好", "url": "/getting-started/hello" }
  ]
}
```

`label` 是这一组的名称。写成字符串时，所有语言共用；写成对象时，每种语言各写一个
名称，以后增加语言就补一个键。同一章节可以有多个分组。对象里缺少当前语言的名称时，
构建会报告配置错误。`text` 是页面名称的备用值。`url` 不写语言，所有语言共用这一份；
打开中文页时，`/getting-started/hello` 会变成 `/zh-CN/getting-started/hello`。数组
顺序就是左侧顺序，也是页底“下一篇”的阅读顺序。页面名称实际取该语言 MDX 的
`title`。这一语言还没写的页面不会出现在它的侧边栏里。

保存后刷新。左侧“入门”里应依次出现“模板概览”“快速开始”“你好”，快速开始页底的
“下一篇”应指向你好。

## 配置 Frontmatter {id="frontmatter"}

`title`、`teaser` 和 `section` 在快速开始里已经用过。这一步给你好页加上 `menu`
，它是页面右侧的小目录。把 `docs/zh-CN/getting-started/hello.mdx` 改成：

```mdx
---
title: 你好
teaser: 我的第一篇文档
section: getting-started
menu:
  - ["下一句", "next"]
---

用 Markdown 写正文即可。

## 下一句 {id="next"}

这一节会出现在页面右侧。
```

字段含义如下：

- `title`：页面标题。
- `teaser`：页面摘要，出现在页面头部说明中。
- `section`：所属大章节，必须与目录名和该语言 `locales.<语言>.sections[].id` 一致。
- `menu`：可选，右侧小目录；每一项是 `[显示文本, 锚点 id]`。

每个 `menu` id 都必须在正文的 `##` 标题上明确声明，例如
`## 下一句 {id="next"}`。显示文字可以不同，但 id 必须完全相同且在页面内唯一。模板
测试会检查缺失锚点。

刷新 `/zh-CN/getting-started/hello`。页首仍是“你好”，右侧应出现“下一句”。点击后 URL 带上
`#next`。

## 再写一页 {id="create-page"}

同一章里再加一页，重复刚才的两步：先写文件，再放进同一组 `items`。

创建 `docs/zh-CN/getting-started/notes.mdx`：

```mdx
---
title: 笔记
teaser: 记在入门里的第二篇
section: getting-started
---

这里可以继续写。
```

然后在“你好”后面加上 `{ "text": "笔记", "url": "/getting-started/notes" }`。

保存后，`/zh-CN/getting-started/notes` 能打开，左侧“你好”的下一篇是“笔记”。侧边栏
配置里的地址仍是 `/getting-started/notes`。

## 新增大章节 {id="new-section"}

上面的步骤只改了已有的“入门”：一篇 MDX，再加一条侧边栏。

新的大章节还要出现在右上角，所以还要改该语言 `locales` 里的 `sections` 和
`navigation`，并在 `website/meta/sidebars.json` 末尾增加一组。完整例子在后面的
[站点配置](/zh-CN/writing/site-configuration)，用虚构产品的“产品指南”走一遍。这一页先不
做。

## 重命名或删除 {id="rename-delete"}

重命名页面时：

1. 重命名 MDX 文件。
2. 修改侧边栏 URL，以及正文、首页和页脚中指向旧 URL 的链接。
3. 如果改了 section id，还要改目录、所有页面 frontmatter、站点配置和侧边栏。

删除页面时先从侧边栏移除链接，再删除文件。模板不会自动为旧 URL 生成重定向；已经
公开的文档若需要兼容旧地址，应在托管平台配置重定向，或暂时保留说明页。

例如把笔记页改名，在仓库根目录运行。`docs/` 在仓库根目录，`meta/` 和 `pages/` 在
`website/` 里：

```bash
git mv docs/zh-CN/getting-started/notes.mdx docs/zh-CN/getting-started/setup.mdx
rg "/zh-CN/getting-started/notes" docs website/meta website/pages
```

把搜索结果中的旧链接全部改为 `/zh-CN/getting-started/setup`，再运行测试。预期测试不再
报告旧 sidebar URL，浏览器能打开新地址。

在 `website/` 目录运行：

```bash
npm test -- --runInBand
npm run build
```

然后打开 `/zh-CN/getting-started/hello` 并检查：

- 页面标题是“你好”，摘要是“我的第一篇文档”。
- 左侧“入门”里能看到它，顺序和 `sidebars.json` 一致。
- 右侧“下一句”点击后滚动到对应标题。
- 直接刷新页面仍能打开。
