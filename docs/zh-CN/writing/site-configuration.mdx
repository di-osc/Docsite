前面几页已经会写页面、组件和图片。这一页改的是整站：大章节、顶部导航和侧边栏。
示例仍用虚构产品 Acme SDK，代表你自己的产品文档。

这一页保留现有使用手册，再为它增加“产品指南”大章节。配置和页面使用同一个章节名
，站点才能把它们连起来。每一步都可以运行测试和预览。自己的内容写好之后，再删除不
需要的模板手册和对应导航。

## 配置文件 {id="locations"}

先了解每个文件负责什么：

| 文件                                 | 作用                                                          |
| ------------------------------------ | ------------------------------------------------------------- |
| `website/meta/site.json`             | 全站共用的仓库和主题色，以及 `locales` 里每种语言的身份与导航 |
| `website/meta/sidebars.json`         | 所有语言共用的章节、分组和页面顺序。`url` 不带语言            |
| `website/meta/type-annotations.json` | 把 MDX 类型标注链接到参考页面                                 |
| `public/manifest.webmanifest`        | 安装到桌面时的名称、显示方式和主题色                          |
| `pages/index.tsx`                    | 根路径上的语言列表                                            |

最常修改的是前两个 JSON 文件。类型映射会在
[MDX 组件](/zh-CN/writing/mdx-components#type-annotations) 中用实际效果解释。根路径
只列出语言，品牌文字放在对应语言的 `locales` 里。

## 字段参考 {id="fields"}

`website/meta/site.json` 分成全站共用字段和 `locales` 里的每种语言：

| 字段         | 作用                               | 示例                     |
| ------------ | ---------------------------------- | ------------------------ |
| `company`    | 左上角和页脚中的组织名称           | `"Acme"`                 |
| `companyUrl` | 页脚组织链接                       | `"https://acme.example"` |
| `repo`       | 源码链接使用的 GitHub `owner/repo` | `"acme/sdk-docs"`        |
| `theme`      | 浏览器 UI 的十六进制主题色         | `"#0a8f6a"`              |
| `locales`    | 每种语言一份配置，键是语言 id      | `"zh-CN"`、`"en"`        |

每种语言里面再写：

| 字段          | 作用                                         |
| ------------- | -------------------------------------------- |
| `label`       | 页头语言切换上的名称                         |
| `lang`        | HTML 语言，如 `zh-CN`、`en`                  |
| `title`       | 这一语言的浏览器标题                         |
| `description` | 这一语言的 SEO 摘要                          |
| `slogan`      | 没有页面标题时，接在站点名称后面的短句       |
| `sections`    | 大章节 id、标题和页面主题。id 与其他语言相同 |
| `navigation`  | 右上角链接。站内地址写带语言前缀的路径       |
| `footer`      | 页脚链接。站内地址同样带语言前缀             |
| `ui`          | 搜索、404、建议修改和下一篇这些短句          |

不设 `defaultLocale`。语言 id 不能和章节 id 重名，否则地址第一段无法区分。

`sections[].theme` 与根级 `theme` 含义不同：

```json
{
  "theme": "#0a8f6a",
  "locales": {
    "zh-CN": {
      "sections": [{ "id": "guide", "title": "产品指南", "theme": "green" }]
    }
  }
}
```

- 根级 `theme` 是浏览器使用的颜色值。
- `sections[].theme` 是模板内置样式名，可选 `blue`、`green`、`purple`、
  `nightly` 或 `legacy`。

## 增加一种语言 {id="locales"}

新增一种语言不用再复制一份侧边栏。目录结构所有语言共用 `sidebars.json`。

1. 新建 `docs/<语言>/`，例如 `docs/ja/`。
2. 在 `site.json` 的 `locales` 里加上同一个语言 id。`sections` 使用和现有语言相同
   的章节 id，并为这一语言写 `label`、`lang`、`title`、`navigation` 和 `footer`。
3. 页面文件按 `sidebars.json` 里已有的路径摆放。配置里的 `/getting-started` 对应
   `docs/ja/getting-started/index.mdx`，公开地址是 `/ja/getting-started`。
4. `navigation` 和 `footer` 里的站内地址要带上这一语言的前缀。`sidebars.json` 的
   `url` 不要加前缀。
5. 为每个按语言配置的 `label` 对象补上新语言的名称；字符串形式的共用名称无需修改。

侧边栏上的页面名称用该语言 MDX 的 `title`。还没写的页面不会出现在这一语言的侧边栏
里。分组标题读取每组 `label` 中对应语言的名称。页头切换在有译文时打开同一页，没有译文时
进入这一语言的第一章。

中文和英文手册已经按同一份侧边栏写齐。再加一种语言时，重复上面的步骤，并补上该语言
的页面文件。

## 配置关系 {id="relationships"}

同一个大章节 id 会出现在这些位置：

```text
docs/zh-CN/guide/index.mdx
     └─ frontmatter: section: guide
meta/site.json
     └─ locales.zh-CN.sections[].id: guide
meta/sidebars.json
     └─ sidebars[].section: guide
     └─ items[].url: /guide
```

公开地址是 `/zh-CN/guide`。`navigation[].url` 写成 `/zh-CN/guide`。侧边栏里的
`url` 仍是 `/guide`，不带语言。侧边栏数组顺序决定页底“下一篇”的顺序。

<Infobox title="新增页面与新增章节不同" variant="warning">

在已有章节中增加页面，只需创建 MDX 并加入侧边栏；增加新的大章节，才需要同时修改
该语言的 `sections`、`navigation`、共用侧边栏和 `docs/<语言>/` 下的文档目录。

</Infobox>

## 完整配置示例 {id="example"}

先在 `locales.zh-CN.sections` 末尾加入：

```json
{ "id": "guide", "title": "产品指南", "theme": "green" }
```

再在同一语言的 `navigation` 末尾加入。这里的地址带语言前缀：

```json
{ "text": "产品指南", "url": "/zh-CN/guide" }
```

最后在 `website/meta/sidebars.json` 的最外层数组末尾加入完整侧边栏对象。`url`
不带语言：

```json
{
  "section": "guide",
  "items": [
    {
      "label": { "zh-CN": "开始使用", "en": "Getting started" },
      "items": [{ "text": "指南概览", "url": "/guide" }]
    }
  ]
}
```

`items` 数组可以包含多个分组，每组使用自己的 `label`，不需要增加 `id`。
上面的分组在中文显示“开始使用”，英文显示“Getting started”；`sections[].title`
仍表示整章名称。字符串 `label` 表示所有语言共用名称；按语言配置的对象缺少当前语言
名称时会报告配置错误。

注意前一个数组元素后要有逗号。完成后，原有手册仍可访问，右上角会多出“产品指南”，
但页面尚未创建。

## 创建入口页面 {id="documents"}

创建 `docs/zh-CN/guide/index.mdx`：

```mdx
---
title: 指南概览
teaser: 从安装到第一个 Acme SDK 请求
section: guide
menu:
  - ["下一步", "next"]
---

这里介绍指南覆盖的内容和适用读者。

## 下一步 {id="next"}

继续阅读安装说明。
```

保存后，顶部“产品指南”打开 `/zh-CN/guide`，左侧显示“指南概览”。如果只写配置而不
创建这个文件，测试会报告侧边栏 URL 找不到页面。

## 再加一篇页面 {id="child-page"}

入口页能打开之后，再用 [添加与组织文档](/zh-CN/writing#create-page) 里的方法给这一章加
第二篇。创建 `docs/zh-CN/guide/installation.mdx`：

````mdx
---
title: 安装
teaser: 安装 Acme SDK 并验证环境
section: guide
menu:
  - ["安装依赖", "install"]
  - ["验证安装", "verify"]
---

## 安装依赖 {id="install"}

```bash
npm install @acme/sdk
```

## 验证安装 {id="verify"}

安装完成后运行项目测试，确认 SDK 可以被正常导入。
````

然后只改 `guide` 那一组的 `items`，在“指南概览”后面加上“安装”。`url` 仍然不带语言：

```json
{
  "label": { "zh-CN": "开始使用", "en": "Getting started" },
  "items": [
    { "text": "指南概览", "url": "/guide" },
    { "text": "安装", "url": "/guide/installation" }
  ]
}
```

保存后，`/zh-CN/guide/installation` 能打开。左侧先是“指南概览”，再是“安装”。页首
是“安装”，右侧有“安装依赖”和“验证安装”。

后续新增“API”等大章节时，重复同样的四步：增加 section、增加带语言前缀的顶部入口、
增加不带语言前缀的侧边栏对象、在 `docs/<语言>/` 下创建入口 MDX。不要一次删除模板
手册；确认自己的页面已经覆盖所需说明后，再同时删除对应文档目录、`sections`、
`navigation` 和侧边栏对象。

## 验证结果 {id="verify"}

在 `website/` 目录运行：

```bash
npm test -- --runInBand
npm run build
```

预期结果：

- 测试不报告 section、frontmatter、sidebar URL 或 menu 锚点错误。
- 构建生成 `/zh-CN/guide` 和 `/zh-CN/guide/installation`。
- 右上角新增“产品指南”，原有模板手册入口仍然可用。
- 打开“产品指南”时使用绿色主题，左侧先是“指南概览”，再是“安装”。

配置结构完成后，继续 [外观定制](/zh-CN/writing/appearance)，修改语言里的站点名称
和主题色。
